## 关键机制事实(新证据)

1. **ACP 凭证走 `_meta`**:`authenticate{methodId:"windsurf-api-key",
   _meta:{api_key, api_server_url}}`(实证自 `dist/extension.js`
   `_authenticateWithWindsurfApiKey`)。裸 `methodId` 触发浏览器 PKCE 挂起。
2. **`_meta.api_server_url` ≠ 数据面权威**:官方值 + 本地 env 并存时,
   数据面仍走 `WINDSURF_API_SERVER_URL` env → spawn-hook 锚定天然覆盖,无旁路。
3. **chisel 模型注册表=0 组**(`Model registry ready … (0 groups)`)→
   `--model`/`DEVIN_MODEL`/`agent.model` 均不解析,恒回退默认 `swe-1-6-fast`。
   **模型替换的正确层级本就是 daoRoutes 路由表**——改
   `routes["swe-1-6-fast"]` 即换真实后端,与 Cascade 替换语义完全一致。
   (另发 `swe-2-high` 调用各自独立判路由。)
4. **SP 载体**:chisel 把 SP 作 **plain_utf8** 置于 field=2(msg[0]),
   非嵌套 ChatMessage —— `modifySPProto` 情形 B 命中。
5. **用户规则独立成 user 消息**(`<rules type="always-on">`,11352B),
   不随 SP 替换消失 —— 与 Cascade(SP 内 `<user_rules>` 被化除)语义有别,
   实际更利用户:agent 身份/契约可换,用户自书规则仍在。
6. **标题子模型**:"You are a session title generator…"(202B)→
   `<500` 低于 isLikelyOfficialSP 门槛 → 原样透传(功能不受扰);
   classify 侧已收 ephemeral 指纹仅作观察分类。

## 已知边界/遗留

- **cold-start**: 代理启动 ~10s 内 GetCliTeamSettings 可超时 → authenticate
  报 "fetch timed out";预热后正常。生产常驻代理无此症。
- **remote_config revalidation 失败(unleash.codeium.com)**:无网/被墙时
  WARN 频出但不阻塞(last-good 缓存)。
- **swe-2-high 未路由**:现默认官方;欲接外接 → `配置.json` 增路由即可。
- **标题生成模型**:同走 GetChatMessage,sysLen=202 低于门槛不动,无碍。
- **Devin 多 SP 形态**:实测 plain_utf8 单条 system;若后续版本改嵌套
  ChatMessage 或多段 role=0,`modifySPProto` 两路情形均覆盖。
- **rules 透传**:chisel `<rules>` 为 user 消息 → 过代理不剥(与 Cascade 差异,
  当前语义 = 用户规则保真)。
